# Go로 작은 HTTP 서버

이 노트는 samsepi0l이 같은 언어 등록부를 Go 표준 라이브러리로 정리한 것입니다. `GET /languages`와 `POST /languages`만 있습니다. 시드는 Python, JavaScript, Go, Rust, TypeScript, Kotlin, Elixir, Zig, Dart, Haskell이고, JSON 필드도 `id`, `name`, `paradigm`, `year`, `summary`로 같습니다.

외부 프레임워크와 외부 모듈은 쓰지 않습니다. 모듈 경로는 `github.com/samsepi0l-1337/lang-study/examples/go`입니다. 경로는 import 이름이지, 컴파일할 때 그 원격 저장소가 필요하다는 뜻이 아닙니다. 수신 주소는 `PORT`이고 기본값은 8090입니다. 테스트는 그 포트를 열지 않습니다.

## 이 장을 끝내면

- `package main`, 구조체, 포인터 메서드가 이 서버에서 맡는 역할을 구분합니다.
- 클라이언트 오류를 `error` 값으로 돌려 상태 코드와 연결합니다.
- 요청 고루틴이 공유하는 슬라이스를 뮤텍스로 지키고, 고루틴을 더 만들지 않는 이유를 설명합니다.

## 패키지는 실행 파일 하나와 같습니다

모든 파일이 `package main`입니다. `languages.go`가 타입과 저장소를, `main.go`가 라우트와 프로세스를, `languages_test.go`가 `httptest`를 담습니다. 같은 패키지이므로 테스트가 `newMux`와 `NewStore`를 직접 호출합니다. 테스트 패키지를 `main_test`로 두면 이름 첫 글자가 소문자인 함수는 보이지 않습니다.

`go.mod`의 `go 1.22`는 `GET /languages`처럼 메서드와 경로를 한 패턴으로 적는 `ServeMux`를 쓰기 위한 하한입니다. 내부 import가 없으므로 `go.sum`도 없습니다.

## 구조체는 저장과 입력을 나눕니다

`Language`는 저장되는 행입니다. `json` 태그가 응답 필드를 정합니다. `LanguageInput`에는 `id`가 없습니다. 번호를 서버가 정하기 위해서입니다. 디코더는 `DisallowUnknownFields`라서 본문에 `id`가 있으면 디코드 자체가 실패하고 400이 됩니다. 알 수 없는 필드를 무시하면 클라이언트가 번호를 보냈다는 사실을 놓칩니다.

시드의 패러다임은 공부장에서의 짧은 분류입니다. Python, JavaScript, Rust, TypeScript, Kotlin은 다중 패러다임, Go와 Zig은 명령형, Elixir는 함수형, Dart는 객체지향, Haskell은 순수 함수형입니다. Rust의 연도는 2015입니다.

## 메서드는 포인터로 같은 잠금을 만집니다

`List`와 `Add`의 리시버는 `*Store`입니다. `Add`가 `nextID`와 슬라이스를 바꾸기 때문만이 아닙니다. `sync.Mutex`를 값으로 복사하면 잠금이 복제본에 걸려 공유가 깨집니다. `go vet`도 락 복사를 지적합니다. 읽기 전용인 `List`도 같은 포인터 리시버로 그 뮤텍스를 잡습니다.

`List`는 락 안에서 `make`한 뒤 `copy`합니다. nil 슬라이스를 JSON으로 인코딩하면 `null`이 되므로, 길이 0이어도 배열로 보이게 비어 있지 않은 헤더를 만듭니다. 지금 시드는 비어 있지 않지만, 반환값을 호출자가 고쳐도 다음 `GET`이 바뀌지 않아야 합니다. 테스트가 첫 항목 이름을 바꾼 뒤 다시 조회하는 이유가 이것입니다.

`Add`는 공백을 자른 뒤 글자 수를 봅니다. `len`은 바이트입니다. `가` 40자는 120바이트라서 `len`으로 40을 넘는지 보면 올바른 한글 이름이 거절됩니다. `utf8.RuneCountInString`으로 룬을 셉니다. 이름과 패러다임은 1룬 이상 40룬 이하, 요약은 1룬 이상 200룬 이하, 연도는 1950부터 2100입니다. 중복 검사는 `strings.EqualFold`이고 락 안에서 합니다. 락 밖에서 검사하면 그 사이에 같은 이름이 들어갈 수 있습니다.

## 오류는 값이고 상태 코드는 핸들러가 고릅니다

`Add`는 `(Language, error)`를 반환합니다. 영 값과 `ErrInvalid`, 영 값과 `ErrDuplicate`, 또는 행과 `nil`입니다. 클라이언트의 잘못된 입력에 `panic`을 쓰지 않습니다. 패닉은 핸들러의 복구 경로가 없으면 그 연결의 처리를 떨어뜨립니다.

핸들러는 `errors.Is`로 센티널을 구분합니다. 이 저장소는 오류를 감싸지 않습니다. 그래도 `==` 대신 `errors.Is`를 쓰는 이유는, 나중에 `fmt.Errorf`에 `%w`를 붙여도 같은 분기가 남게 하기 위해서입니다. 잘못된 JSON과 범위 오류는 400, 중복은 409, 성공은 201입니다. 500은 지금 분기에서 나오지 않는 나머지 오류를 위한 자리입니다.

## 고루틴은 서버가 이미 만듭니다

`net/http`는 연결을 받아들이면 그 연결을 읽는 고루틴을 만듭니다. 핸들러는 그 고루틴 위에서 실행됩니다. HTTP/1.1에서 한 연결의 요청은 그 고루틴에서 순서대로 처리되고, 다른 연결의 `List`와 `Add`는 겹칠 수 있습니다. 그래서 슬라이스와 `nextID`를 뮤텍스로 직렬화합니다. 락은 읽고 쓰는 동안만 잡고 `defer`로 풀어, 오류로 `return`해도 잠금이 남지 않게 합니다.

이 코드는 `go` 키워드로 고루틴을 만들지 않습니다. 직접 만든 고루틴은 누가 끝내는지, 패닉을 어디서 받는지, 결과를 어디로 보내는지를 작성자가 책임집니다. 백그라운드 루프를 추가하면 프로세스를 끌 때 그 루프를 멈추는 코드가 필요합니다. 요청 처리가 끝나면 할 일도 끝나는 서버에는 그 책임이 없습니다.

## 예제

파일은 `examples/go/go.mod`, `languages.go`, `main.go`, `languages_test.go`입니다.

`examples/go/languages.go`의 두 구조체입니다. 입력 구조체에는 id가 없습니다.

```go
type Language struct {
	ID       int    `json:"id"`
	Name     string `json:"name"`
	Paradigm string `json:"paradigm"`
	Year     int    `json:"year"`
	Summary  string `json:"summary"`
}

type LanguageInput struct {
	Name     string `json:"name"`
	Paradigm string `json:"paradigm"`
	Year     int    `json:"year"`
	Summary  string `json:"summary"`
}
```

`examples/go/languages.go`의 `Add`입니다. 범위 검사는 락 앞이고, 중복 검사는 락 안입니다.

```go
func (s *Store) Add(in LanguageInput) (Language, error) {
	name := strings.TrimSpace(in.Name)
	paradigm := strings.TrimSpace(in.Paradigm)
	summary := strings.TrimSpace(in.Summary)
	if name == "" || utf8.RuneCountInString(name) > 40 ||
		paradigm == "" || utf8.RuneCountInString(paradigm) > 40 ||
		summary == "" || utf8.RuneCountInString(summary) > 200 ||
		in.Year < 1950 || in.Year > 2100 {
		return Language{}, ErrInvalid
	}
	s.mu.Lock()
	defer s.mu.Unlock()
	for _, row := range s.items {
		if strings.EqualFold(row.Name, name) {
			return Language{}, ErrDuplicate
		}
	}
	created := Language{
		ID:       s.nextID,
		Name:     name,
		Paradigm: paradigm,
		Year:     in.Year,
		Summary:  summary,
	}
	s.nextID++
	s.items = append(s.items, created)
	return created, nil
}
```

`examples/go/main.go`는 패턴 문자열로 메서드를 구분합니다. `listenAddr`만 `PORT`를 읽고, 테스트는 `newMux`에 `httptest.ResponseRecorder`를 넘깁니다.

```go
	mux.HandleFunc("GET /languages", func(w http.ResponseWriter, r *http.Request) {
		writeJSON(w, http.StatusOK, store.List())
	})
	mux.HandleFunc("POST /languages", func(w http.ResponseWriter, r *http.Request) {
		var in LanguageInput
		dec := json.NewDecoder(r.Body)
		dec.DisallowUnknownFields()
		if err := dec.Decode(&in); err != nil {
			writeJSON(w, http.StatusBadRequest, map[string]string{"error": "JSON 본문을 해석할 수 없습니다"})
			return
		}
		created, err := store.Add(in)
		if errors.Is(err, ErrInvalid) {
			writeJSON(w, http.StatusBadRequest, map[string]string{"error": err.Error()})
			return
		}
		if errors.Is(err, ErrDuplicate) {
			writeJSON(w, http.StatusConflict, map[string]string{"error": err.Error()})
			return
		}
		if err != nil {
			writeJSON(w, http.StatusInternalServerError, map[string]string{"error": "저장에 실패했습니다"})
			return
		}
		writeJSON(w, http.StatusCreated, created)
	})
	return mux
```

`examples/go`에서 `go test`를 실행합니다. 테스트는 열 개 조회, 복사본 격리, OCaml 추가와 id 11, 대소문자 중복, 깨진 JSON, 룬 40자와 41자를 확인합니다. 서버를 직접 띄울 때만 포트가 필요합니다.

```bash
go test
PORT=8090 go run .
```

## 연습

1. `{}`를 `POST /languages`로 보내 400을 확인합니다. 이름, 패러다임, 요약, 연도 중 어느 조건이 `ErrInvalid`에 걸리는지 `Add`에서 가리킵니다.
2. `가` 40룬이 201이고 41룬이 400인지 재현합니다. 같은 40룬을 `len`으로 재면 바이트가 120이라 잘못 거절된다는 점을 숫자로 적습니다.
3. `GET`으로 받은 첫 항목의 `Name`만 바꾼 뒤 다시 `GET`합니다. 저장소가 Python으로 남는 이유가 `make`와 `copy`인 지점을 표시합니다.

## 스스로 확인

1. 값 리시버로 락을 잡으면 무엇이 잘못됩니까?

리시버가 `Store` 값이면 뮤텍스가 복사됩니다. 복사된 락을 잠그면 다른 고루틴이 원본 락으로 지키는 슬라이스와 동기화되지 않습니다. 그래서 변경이 없는 `List`도 포인터 리시버를 사용합니다.

2. 한글 이름에 len을 쓰면 어떤 거절이 납니까?

`len`은 바이트 수입니다. UTF-8에서 `가`는 3바이트이므로 룬 40자가 길이 제한 40을 넘습니다. `utf8.RuneCountInString`이 글자 수에 해당하는 룬을 셉니다. 테스트 `TestKoreanNameUsesRuneCount`가 그 차이를 고정합니다.

3. errors.Is는 이 코드에서 무엇을 구분합니까?

`ErrInvalid`와 `ErrDuplicate`를 구분합니다. 지금 `Add`는 오류를 감싸지 않지만, `errors.Is`는 감싼 뒤에도 같은 센티널을 찾습니다. 두 오류의 상태 코드는 400과 409로 다릅니다.

4. go test가 PORT 없이 핸들러를 호출하는 이유는 무엇입니까?

`httptest.NewRequest`와 `NewRecorder`가 `ServeHTTP`를 직접 호출하기 때문입니다. `main`의 `ListenAndServe`는 테스트에서 실행되지 않습니다. 포트 충돌과 환경 변수가 목록 규칙 테스트를 좌우하지 않습니다.

5. 다른 연결의 요청이 겹치는데도 go 키워드가 없는 이유는 무엇입니까?

연결을 처리하는 고루틴은 `net/http`가 이미 만듭니다. 공유 상태는 뮤텍스로 충분합니다. 추가로 띄운 고루틴은 종료와 패닉과 결과 전달을 이 프로그램이 맡게 되므로, 요청 안에서 끝나는 일에는 만들지 않습니다.
