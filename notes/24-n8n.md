# n8n 워크플로

이 장은 samsepi0l이 n8n의 데이터 흐름을 언어 카드 하나로 정리한 노트입니다.
워크플로는 웹훅으로 시작해 Set 노드에서 끝납니다.
제목과 요약만 만듭니다.
자격 증명의 값은 파일에 없습니다.
특정 제품 버전에서만 되는 노드를 더하지 않습니다.
Webhook과 Set은 오래 유지된 노드입니다.
화면의 표시 이름이 Edit Fields인 경우가 있습니다.
파일의 type은 그때도 n8n-nodes-base.set입니다.

## 이 장을 끝내면

- 트리거, 노드, 아이템이 서로 무엇을 넘기는지 말합니다.
- 웹훅 본문의 언어 이름을 `{{ $json.body.language }}`로 읽습니다.
- 비밀은 값이 아니라 자격 증명 참조로 남긴다는 점과, 실패 시 에러 워크플로가 따로 돈다는 점을 설명합니다.

## 트리거

워크플로는 시작점이 필요합니다.
시작점이 트리거입니다.
이 파일의 트리거는 Webhook입니다.
HTTP POST가 경로 language-card로 들어오면 실행이 하나 생깁니다.
active는 false입니다.
파일을 두었다는 뜻이지, 지금 어떤 서버가 그 경로를 듣고 있다는 뜻이 아닙니다.

수동 실행용 트리거와 일정 트리거도 있습니다.
이 장은 그 둘을 넣지 않습니다.
카드의 입력은 HTTP 본문이면 충분합니다.

웹훅에는 인증을 붙이지 않았습니다.
공부용 문서이므로 공개 주소에 그대로 올려 쓰는 설정이 아닙니다.
나중에 인증을 붙이면 그 비밀도 아래의 자격 증명 규칙을 따릅니다.

responseMode는 lastNode입니다.
웹훅이 마지막 노드의 출력을 HTTP 응답으로 쓰게 하려는 값입니다.
응답 본문을 따로 만드는 노드는 두지 않았습니다.

## 노드와 아이템

노드는 작업 한 칸입니다.
이 워크플로의 노드는 두 개입니다.
이름은 Webhook과 Set이고, type은 n8n-nodes-base.webhook과 n8n-nodes-base.set입니다.

노드 사이에는 아이템이 지나갑니다.
아이템은 배열입니다.
원소는 json을 가지고, 파일이 있으면 binary를 따로 가집니다.
이번 카드에는 파일이 없습니다.

JSON 본문을 받는 웹훅 아이템의 json은 대체로 headers, params, query, body로 나뉩니다.
보낸 객체는 body 아래에 있습니다.
본문이 `{ "language": "Rust" }`이면 언어 이름은 body.language입니다.
json의 맨 위에 language가 있는 것이 아닙니다.

Set은 아이템마다 필드를 다시 씁니다.
요청이 하나면 아이템도 하나입니다.
앞 노드가 아이템을 두 개 내면 Set도 두 번 도는데, 이 워크플로는 그렇게 만들지 않습니다.

연결은 노드 id가 아니라 이름으로 적습니다.
Webhook의 main 출력 0번이 Set의 입력으로 이어집니다.
`examples/n8n/validate.mjs`가 이 type 두 개와 그 연결을 확인하고, 없으면 예외를 던집니다.
Set의 매개변수에 title과 summary라는 이름이 있는지도 봅니다.

## 표현식

표현식은 `{{ }}` 안입니다.
`$json`은 지금 아이템의 json입니다.
웹훅 다음 노드에서 언어 이름을 읽으려면 `{{ $json.language }}`는 맞지 않습니다.
그 식은 json 맨 위에 language가 있을 때의 식입니다.
Set이 만든 다음 노드라면 title이 맨 위에 있으므로 `{{ $json.title }}`이 맞습니다.
웹훅 바로 다음인 Set 안에서는 body를 거쳐야 합니다.

```text
{{ $json.body.language }}
```

저장한 JSON에서 식 필드는 앞에 `=`가 붙는 경우가 많습니다.
등호는 그 칸이 표현식 모드라는 표시입니다.
파일에는 이렇게 적혀 있습니다.

```text
={{ $json.body.language }}
```

title은 그 식만 넣습니다.
summary는 같은 식 뒤에 공백과 `학습 카드`를 붙입니다.
Rust를 보내면 제목은 Rust, 요약은 `Rust 학습 카드`가 되게 하려는 구성입니다.
language가 없으면 식의 결과는 비어 있고, 워크플로는 다른 문장을 만들어 주지 않습니다.
기본값을 식 안에 넣지 않은 것은, 없는 필드를 숨기지 않기 위해서입니다.

## 자격 증명은 참조만

이 워크플로 JSON에는 credentials가 없습니다.
Set과 Webhook이 비밀을 쓰지 않기 때문입니다.

노드가 외부 서비스의 비밀을 필요로 하면, 내보낸 JSON에 남는 것은 자격 증명의 id와 이름입니다.
비밀 값은 n8n의 자격 증명 저장소에 있습니다.
워크플로 파일에 토큰을 붙여 넣지 않습니다.
저장소에도 붙여 넣지 않습니다.
이름을 비밀처럼 길게 짓는 것도 피합니다.
내보내기 파일에 이름이 남기 때문입니다.

## 에러 워크플로

실패를 알리는 흐름은 같은 캔버스에 억지로 붙이지 않고 워크플로를 하나 더 둡니다.
그 워크플로의 첫 노드는 Error Trigger입니다.
언어 카드 워크플로의 설정에서 Error workflow로 그 워크플로를 고릅니다.
실행이 실패하면 그쪽이 돕니다.
하나의 에러 워크플로를 여러 워크플로가 같이 쓸 수 있습니다.

수동 실행으로는 Error Trigger가 돌지 않습니다.
자동으로 시작된 실행이 실패할 때 동작합니다.
그래서 편집 화면에서 시험 실행만으로는 알림 경로가 확인되지 않습니다.

실패가 트리거 다음 노드에서 나면, 넘어오는 데이터에는 워크플로 id와 이름, 오류 메시지, 마지막으로 실행된 노드 이름이 포함되는 것이 기본입니다.
execution.id와 실행 주소는 실행이 저장되었을 때만 있습니다.
트리거 자체가 실패하면 실행이 만들어지지 않아 그 id가 없고, 데이터 모양이 달라집니다.
다시 시도한 실행일 때만 retryOf가 있습니다.

이 장의 JSON에는 에러 워크플로를 넣지 않았습니다.
설계만 적어 둡니다.
알림 문장에는 워크플로 이름과 오류 메시지를 넣고, 자격 증명의 값은 넣지 않습니다.

## 예제

`examples/n8n/language-card.workflow.json`의 Set은 웹훅 본문에서 카드 두 필드를 만듭니다.

```json
        "values": {
          "string": [
            {
              "name": "title",
              "value": "={{ $json.body.language }}"
            },
            {
              "name": "summary",
              "value": "={{ $json.body.language }} 학습 카드"
            }
          ]
        },
```

같은 파일의 연결입니다.

```json
  "connections": {
    "Webhook": {
      "main": [
        [
          {
            "node": "Set",
            "type": "main",
            "index": 0
          }
        ]
      ]
    }
  }
```

확인은 `node examples/n8n/validate.mjs`입니다.
노드나 연결이 없으면 예외로 끝납니다.
통과하면 ok를 출력합니다.

## 연습

1. summary의 고정 문장만 바꿉니다. title 식은 `={{ $json.body.language }}`로 유지하고 validate를 다시 실행합니다.
2. 본문에 reason이 있다고 가정하고 Set의 string 목록에 reason 필드를 하나 추가합니다. 연결은 그대로 둡니다.
3. 에러 워크플로가 받을 문장을 글로 적습니다. 워크플로 이름과 오류 메시지만 포함하고 토큰은 적지 않습니다.

## 스스로 확인

### 1. 웹훅에 `{ "language": "Zig" }`를 보내면 Set은 어디서 이름을 읽습니까?

답: 현재 아이템의 `$json.body.language`입니다. `$json.language`는 맨 위에 language가 있을 때의 식입니다.

### 2. 연결 객체의 키는 노드 id입니까?

답: 아닙니다. 출발 노드의 이름입니다. 이 파일에서는 Webhook이고, 도착 노드 이름은 Set입니다.

### 3. 자격 증명을 파일에 어떻게 남깁니까?

답: 남긴다면 id와 이름 같은 참조입니다. 비밀 값은 자격 증명 저장소에 두고 워크플로 JSON이나 저장소에 적지 않습니다. 이번 파일에는 참조도 없습니다.

### 4. 편집 화면의 수동 실행으로 에러 워크플로를 확인할 수 있습니까?

답: 없습니다. Error Trigger는 자동 실행이 실패할 때 동작합니다. 첫 노드는 Error Trigger이고, 설정에서 Error workflow로 연결합니다.

### 5. validate.mjs는 무엇을 실패로 봅니까?

답: Webhook type이나 Set type이 없거나, Webhook의 main 연결이 Set으로 가지 않거나, Set 매개변수에 title과 summary가 없으면 예외를 던집니다.
